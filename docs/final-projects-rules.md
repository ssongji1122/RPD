# 기말 작품 아카이브 공개 규칙

기말 작품 페이지(`/final-projects`)와 홈 필름스트립은 누구나 볼 수 있는 공개 페이지입니다. 학생 작업을 외부(교수·심사·방문자)에 보여 줄 때 아래 규칙을 지킵니다. 데이터는 `course-site/data/final-projects.js`, 화면 규칙 코드는 `web/src/data/fpDisplay.ts`, 이미지 제외 목록은 `web/src/data/fpCuration.ts`에 있습니다.

## 1. 개인정보

- 학번 · 실명 · 이메일 · 전화번호가 보이는 자산은 올리지 않고, 이미 올라간 것은 `FP_EXCLUDE`에 넣어 화면에서 뺍니다.
- 학생 외부 사이트 · Canva · Google Slides · Behance는 페이지 안에 iframe으로 띄우지 않고 「새 탭에서 열기」 링크로만 연결합니다. 외부 화면은 표지나 본문에 학번 · 실명이 있는 경우가 많고, 학생이 언제든 내용을 바꿀 수 있어 이쪽에서 통제할 수 없기 때문입니다. 이 사이트에 직접 올리고 개인정보가 없음을 확인한 자산(`assets/...`)만 iframe으로 띄웁니다.
- 학생 노트에 들어 있는 로컬 경로(`file:///`, `C:/Users/<이름>/` 등)는 화면에 보이지 않게 거릅니다(`isPublicNote`). 로컬 경로에는 PC 사용자명이 드러나고, 방문자가 열 수도 없습니다.
- 작품명에 실명이 들어 있으면 이름을 빼고 씁니다.

## 2. 외부 링크

- Canva 단축 링크(`canva.link`)는 학생 공유 설정에 따라 로그인하지 않은 방문자에게도 편집 화면으로 열립니다. 데이터에 해석해 둔 보기 전용 주소(`/view`)로 연결합니다(`publicLinkUrl`).
- 링크 상태는 공유 직전에 한 번 확인합니다. Behance와 Canva는 자동 요청(curl)에 403을 돌려주므로, 브라우저로 열어 판정합니다.

## 3. 작품명

- 작품명의 근거는 화면에 보이는 내용으로 한정합니다. 발표 덱의 「이름:」 줄, 캐릭터 시트, 학생 사이트 본문의 제목, 제출 노션의 문구가 근거가 됩니다.
- 학생 사이트의 탭 제목(`<title>`)만으로 작품명을 정하지 않습니다. 템플릿이나 다른 사람의 사이트를 복제하면 다른 작품 이름이 남아 있을 수 있습니다(2026-11-13: project-13이 「BOMULI」로, project-16이 「ROBO:KUN」으로 잘못 붙어 있었습니다).
- 근거가 없으면 지어내지 않고 익명 코드(`Project NN`)를 유지합니다. 2026-11-13 기준으로 05 · 08 · 11 · 20이 여기에 해당하며, 학생에게 확인을 받아야 채울 수 있습니다.
- 작품명은 `workTitle`에 넣고, 커밋 메시지에 작품별 근거를 적습니다.

## 4. 화면 일관성

- 제목과 개수는 필름스트립과 작품 상세가 같은 함수(`displayTitle`, `projectCounts`)로 계산합니다. 페이지마다 따로 세지 않습니다.
- 개수는 화면에 실제로 보이는 것만 셉니다. `FP_EXCLUDE`에 든 자산은 빼고, 이미지는 완성 컷만 세며, 과정 캡처는 별도 항목으로 셉니다.

## 5. 자산 커밋

- `.gitignore`가 `*.mp4`를 일괄 제외하므로, 영상은 `git add -f <경로>`로 추가합니다. 자산을 옮길 때도 새 위치에서 다시 강제 추가해야 합니다.
- CI의 `tools/check_final_project_assets.py`가 데이터가 가리키는 자산 경로를 모두 `git ls-files`와 대조합니다. 이 검사가 실패하면 빠진 파일을 강제 추가한 뒤 다시 올립니다.

## 6. 공유 전 점검

교수님 등 외부에 링크를 보내기 전에 아래를 확인합니다.

1. 배포된 페이지에서 깨진 이미지 · 영상이 없는지 확인합니다(페이지 안에서 각 자산에 HEAD 요청).
2. 외부 링크가 열리는지 브라우저로 확인합니다.
3. 375px 폭에서 가로 넘침이 없는지 확인합니다.
4. 학번 · 이메일 · 전화번호 패턴이 페이지 텍스트에 없는지 확인합니다.
