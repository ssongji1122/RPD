## 1. 배경 / 목적

Week 15 기말 발표의 순서를 정하는 도구가 현재 lecture-note에 "랜덤 추첨"이라고만 적혀 있다([weeks/week14-final-project/lecture-note.md:274](../../../weeks/week14-final-project/lecture-note.md)). 이를 **실제로 동작하는 사다리타기 게임**으로 대체한다.

## 3. 산출물 ① — 게임 페이지

### 3.1 파일 구조
- `course-site/ladder.html` — 마크업 (신규)
- `course-site/assets/page-ladder.css` — 페이지 스타일 (신규)
- `course-site/assets/ladder.js` — 게임 로직 (신규)
- 재사용: `assets/tokens.css`, `assets/components.css`

### 3.2 레이아웃 결정
- **독립형(standalone)**: 사이트 rail/topbar(`layout.css` 앱 셸)를 쓰지 **않는다**. 수업 중 프로젝터에 띄우는 집중 화면이므로 중앙 정렬 단일 컬럼.
- 좌상단 "← RPD" 텍스트 링크로 사이트 복귀 경로만 제공.
- **week.html의 Notion 렌더러는 건드리지 않는다.** (SSoT 파이프라인 리스크 회피 — [[rpd-render-pipeline]])

### 3.3 화면 흐름 (상태 머신)
1. **설정(setup)**: 참가자 입력
   - 모드 A: textarea에 이름 줄바꿈 입력
   - 모드 B: 인원수 N만 입력 → "1번"~"N번" 자동 라벨
   - "사다리 만들기" 버튼
2. **준비(ready)**: SVG 사다리 렌더 (가로줄 랜덤 생성 완료), 하단에 발표순번 1~N 배치
3. **추첨(drawing)**: 기본은 **한 명씩 공개**(참가자 클릭 또는 자동 순차) — 경로 추적 애니메이션으로 내려가 순번 도착. 별도 "전체 공개" 버튼으로 한 번에 모두 표시 가능.
4. **결과(result)**: "이름 → N번 발표" 매핑표 + "다시 뽑기" / "이름 수정"

### 3.4 사다리 알고리즘 (Amidakuji)
- N명 → N개 세로줄(column)
- 가로줄(rung): 인접한 두 세로줄 사이 랜덤 높이에 배치. **제약**: 같은 높이에서 한 세로줄에 가로줄 2개가 동시에 닿지 않도록(인접 rung 충돌 금지) — bijection(일대일 대응) 보장.
- 가로줄 개수: 대략 `N * 1.5 ~ N * 2` (충분한 섞임). 너무 적으면 결과가 뻔함.
- 경로 추적: 각 참가자는 자기 세로줄 top에서 시작 → 내려가다 가로줄 만나면 좌/우 이동 → bottom 도착. 도착한 bottom 위치의 순번이 결과.
- **공정성**: 사다리타기는 수학적으로 일대일 대응이므로 두 참가자가 같은 순번을 받지 않음(중복 없음).

### 3.5 렌더링 — SVG
- 세로줄/가로줄: `<line>`
- 경로 하이라이트: 참가자 경로를 `<polyline>`로 계산 → `stroke-dasharray`/`stroke-dashoffset` transition으로 "위에서 아래로 그려지는" 효과
- 하이라이트 색: `--key`(#00bfa5) 계열
- canvas 대비 SVG 선택 이유: 선명(벡터)·반응형·경로 애니메이션이 CSS로 간결·디버깅/접근성 유리

### 3.6 디자인 (DESIGN.md 100% 준수)
> **정정 기록**: 73일 된 메모리는 "글래스모피즘"이었으나 SoT인 [DESIGN.md](../../../DESIGN.md)는 2026-04-06 **Flat Outline**으로 전환. 이 문서를 따른다.

- 미감: Flat Outline (Linear/Raycast 톤). gradient/radial-glow/backdrop-blur/box-shadow halo **전부 금지**.
- 색: `--bg`(#0a0a0a), `--surface`(#141517), `--line`, accent `--key`(#00bfa5)/`--key-soft`(#6ee8d8)
- 타이포: Noto Sans KR. 발표순번 숫자에 `font-variant-numeric: tabular-nums`. 한글 `word-break: keep-all`.
- 간격/라디우스: `--sp-*`, `--radius*` 토큰만 사용. **인라인 px 금지** → 새 값 필요 시 토큰 먼저.
- 버튼: `.btn-primary`(민트) / `.btn-ghost` 패턴.

### 3.7 모션 (DESIGN.md 예외 — 사용자 승인 완료)
- DESIGN.md는 "Minimal-functional, decorative keyframes 금지"이나, **이 페이지 한정으로 경로 추적 애니메이션을 허용**한다(2026-06-08 사용자 동의). 근거: 사다리타기에서 "줄 따라 내려가는 시각화"는 장식이 아니라 *결과 도출 과정을 보여주는 핵심 기능*.
- 허용: 경로 stroke 드로잉, 결과 라벨 fade-in.
- 배제: 장식성 파티클·글로우·남발되는 입장 효과.
- **`prefers-reduced-motion` 존중 필수**: 켜져 있으면 애니메이션 생략하고 결과 즉시 표시.

### 3.8 데이터 / 보안
- 전부 브라우저 클라이언트 사이드. 외부 호출 0, `grading_db` 무관.
- 저장: **기본 미저장**(새로고침 시 초기화). 이름 목록 localStorage 복원은 범위 밖(YAGNI).
- innerHTML 사용 시 사이트 규약대로 `escHtml()`/`setHtml()` 패턴 준수(이름이 사용자 입력이므로 XSS 방지 필수).

### 3.9 엣지 케이스
- 0~1명: 2명 미만이면 "사다리 만들기" 비활성 + 안내("최소 2명 필요").
- 중복 이름: 허용(동명이인). 결과표에 입력 순서대로 표기.
- 공백/빈 줄: trim 후 빈 항목 제거.
- 대규모(예: 40명+): 세로줄 폭 축소 + 가로 스크롤. 가독성 한계 안내.
- 반응형: 프로젝터(와이드)·노트북·태블릿 대응. DESIGN.md 브레이크포인트 참고.

### 3.10 접근성
- 키보드: 모든 버튼 포커스 가능, Enter로 진행.
- 스크린리더: 결과 매핑을 `aria-live` 영역에 텍스트로도 제공(SVG만으로 끝내지 않음).
- 색 의존 금지: 경로 하이라이트에 이름 라벨 동반.

## 4. 산출물 ② — 바이브코딩 튜토리얼 콘텐츠

### 4.1 형식 (A안 + 강사 테스트 분담)
- **단계별 프롬프트 회고**: 게임을 만들며 실제로 사용한 프롬프트를 단계별로 정리.
- 각 단계 구성: ① 실제 프롬프트 텍스트 → ② 그 단계의 **우리 게임 스크린샷**(내가 캡처) → ③ 도구 화면 캡처 **placeholder**(강사가 채움) → ④ "어느 바이브코딩 도구든 이 프롬프트 그대로 붙여넣으면 된다" 안내.
- 끝에 **게임 페이지 링크 버튼**.

### 4.2 역할 분담
- **Claude(나)**: 게임 제작 + 튜토리얼 초안(프롬프트 + 우리 게임 스크린샷) 작성. 도구 캡처 자리는 placeholder.
- **강사**: 프롬프트를 실제 도구(Lovable/v0 등)에 넣어 동작 테스트 → 검증 + (원하면) placeholder에 도구 스크린샷 추가.
- 이 분담으로 A안의 유일한 약점(외부 도구 재현 비용)을 제거하고, 강사가 직접 검증한 프롬프트가 됨.

### 4.3 배치 / 발행 경로
- 위치: 14주차 Notion 페이지 ⑦포트폴리오 섹션 하단에 "예제: AI로 발표순서 사다리타기 만들기" 추가.
- 방식: Notion **connector**로 append(원본 보존). 직접 `week14.json` 편집 금지(SSoT).
- 초안: `claudedocs/research/week14-ladder-tutorial.md`에 먼저 작성 후 connector 반영.
- **제약**: 로컬 `NOTION_TOKEN` 401 → 사이트 반영은 ~30분 cron sync 후. 게임 페이지(repo)는 즉시 배포.
